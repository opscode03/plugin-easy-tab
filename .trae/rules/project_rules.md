# Easy Tab 项目 AI 约束规则

## 1. 会话与协作规则

- 本文件是项目级强制规则。每次 AI 对话开始处理任务前，必须先阅读并遵守本文件。
- 涉及界面、交互或视觉修改时，同时阅读根目录 `.uicraft.md`，保持既有设计方向一致。
- 默认使用中文回复、中文界面文案和中文错误提示；代码标识符使用英文。
- 修改任何文件前先读取相关实现，不凭猜测改代码，不修改未了解的文件。
- 只完成用户当前要求，采用满足需求的最小实现，不主动重构、增加配置或扩展功能。
- 优先修改现有文件；只有职责清晰且确有必要时才新增文件或依赖。
- 未经用户明确要求，不创建额外文档，不执行 Git commit 或 push，不删除已有版本和数据。

## 2. 项目边界

- 主要开发目录：`easy-tab-react/`，所有新功能默认在此实现。
- `easy-tab/` 是保留的原生 HTML/CSS/JavaScript 版本，除非用户明确要求，不得同步修改或删除。
- Chrome 扩展构建目录：`easy-tab-react/dist/`。
- 扩展打包产物：`easy-tab-react/easy-tab-chrome.zip`。
- 不直接手工编辑 `dist/` 中的构建产物；应修改源码后重新构建。

## 3. 固定技术栈

- 使用 React 18、JavaScript JSX、Tailwind CSS 3、Vite 6 和 Chrome Manifest V3。
- 不擅自改为 TypeScript、Next.js、Vue、其他构建工具或 CSS-in-JS 方案。
- 图标统一使用现有 `lucide-react`，不新增另一套图标库。
- 使用 Vite `base: "./"`，扩展资源必须保持相对路径。
- `public/manifest.json` 是清单源文件，构建时自动复制到 `dist/manifest.json`。
- 新依赖必须有明确必要性，优先使用浏览器原生能力和现有依赖。

## 4. React 与 JavaScript 写法

- 使用函数组件和 Hooks，保持现有项目结构，不引入 class 组件。
- 保持现有格式：双引号、分号、两空格缩进、`async/await`。
- 事件处理函数使用 `handleXxx`，布尔状态使用 `is/show/has/can` 等清晰命名。
- 组件只负责自身职责；跨组件共享状态继续由 `App.jsx` 统一管理。
- 异步操作必须处理失败状态，并为用户操作提供明确反馈。
- Effect 必须正确清理定时器、事件监听器和订阅，依赖数组必须完整。
- 避免读取过期状态；涉及连续或异步更新时使用现有 `stateRef` 模式。
- 不为一次性逻辑创建过度抽象，不添加无法发生的错误分支或假设性配置。
- 仅在逻辑不直观时添加简短中文注释，不为显而易见的代码补注释。

## 5. 状态与数据规则

- 默认数据、数据规范化和 URL 处理集中在 `src/data.js`。
- 数据读写集中在 `src/storage.js`，业务组件不得各自建立存储通道。
- 扩展环境使用 `chrome.storage.sync` 同步设置和常用入口；普通网页开发环境保留 `localStorage` 回退。
- 保留现有存储键 `easy-tab-state-v1` 和旧数据迁移能力，不得导致老用户数据丢失。
- 新增设置字段时，必须同时更新默认值、`normalizeState()`、设置草稿和保存流程。
- 对旧数据中缺失的布尔字段显式回退到合理默认值，禁止直接用 `Boolean(undefined)` 改变旧用户默认行为。
- 所有保存后的状态都必须经过规范化；外部 URL、收藏夹和用户输入在系统边界校验。
- 多端同步采用最后写入生效，不擅自引入后端、账号系统或复杂冲突解决机制。
- 导入浏览器收藏时使用 `chrome.bookmarks`，支持选择导入并过滤重复网址；入口只放在设置面板最底部，首屏不得出现，且仅在点击后读取收藏夹。

## 6. Chrome 扩展规则

- 保持 Manifest V3 和 `chrome_url_overrides.newtab` 新标签页实现。
- 权限保持最小化；当前权限为 `storage` 和 `bookmarks`。新增权限必须确有必要并向用户说明。
- 不加载远程脚本、远程样式或 CDN 资源，不违反 Chrome 扩展 CSP。
- 不擅自引入服务端依赖、遥测、广告、资讯流或无关账号体系。
- `npm run dev` 用于普通浏览器界面热更新；加载的 `dist` 扩展修改后必须重新构建并在 `chrome://extensions` 重新加载。
- 调用仅扩展环境具备的 API 时，必须保留网页开发模式的兼容行为或明确提示。

## 7. 视觉与样式规则

- 保持“轻量、简洁、平静”的新标签页定位，首屏优先服务时间、搜索和常用入口。
- 主题固定为三项：浅色 / 深色 / 跟随系统；跟随系统必须真实监听系统深浅变化。
- 浅色遵循 Notion 式温暖极简：暖白 `#f6f5f4` 纯平背景、暖中性灰阶、1px 极低对比边框；层级只用字重与留白，不使用阴影、色块分区、玻璃、模糊与渐变。
- 深色遵循 Linear 式暗色克制：冷调近黑 `#0b0d12`，面板层级只用半透明白色叠加，唯一强调色只用于主按钮、选中态与焦点环；禁止外发光、彩色阴影与彩色渐变。
- 优先使用 Tailwind 语义色：`canvas`、`surface`、`panel-1`、`panel-2`、`menu`、`ink`、`ink-muted`、`ink-faint`、`line`、`divider`、`accent`、`danger`，不分散硬编码新色值。
- 复用 `src/index.css` 中现有组件类和 CSS 变量，避免重复定义相同按钮、输入框和弹窗样式。
- 保持移动优先响应式布局，兼容窄屏、宽屏和安全区域；页面严格铺满视口，不出现页面级滚动条。
- 时间使用 `font-clock` 本地字体栈（`Segoe UI Variable Display` / `SF Pro Display` / `Segoe UI` 等），主时间 350 字重、`clamp(42px,min(14vw,9vh),88px)`、字距 `-0.045em`，数字启用 `tabular-nums` 与 `tnum`；正文使用系统无衬线字体；不得引入网络字体。
- 禁止阴影、玻璃拟态、`backdrop-blur`、彩色渐变与任何发光光效。
- 深色模式继续使用根元素 `dark` 类及 CSS 变量，必须同时检查浅色和深色可读性。
- Tailwind 任意值中的 `calc()` 运算符空格使用下划线，例如 `calc(100%_-_32px)`。

## 8. 交互与无障碍规则

- 所有按钮、输入框和开关必须具有可访问名称、可见焦点和正确类型。
- 弹窗优先复用现有 `Modal` 和原生 `<dialog>`，保留 Escape、焦点约束和点击外部关闭。
- 键盘快捷键在输入状态或弹窗打开时不得误触发；对应功能隐藏时快捷键也应失效。
- 加载、空数据、失败、保存中、禁用和成功反馈必须状态一致。
- 动画保持短促克制，并继续支持 `prefers-reduced-motion`。
- 不仅依赖颜色表达错误、选中或禁用状态。
- 全局阻止浏览器原生右键菜单，但必须保留应用自定义右键菜单；全局禁用文本拖选，输入框、文本域、设置输入与 `.selectable` 显式恢复选中；不得影响拖拽排序、点击、双击与键盘复制。
- 分组筛选只保留「全部」与用户分组，不提供「未分组」；分组支持现有拖拽排序持久化，右键 / `F10` / `Shift+F10` 打开自定义菜单，删除后入口回到「全部」。

## 9. 修改与交付检查

- 功能完成后执行语言诊断检查，确保没有新增错误。
- 涉及源码或清单修改后，在 `easy-tab-react/` 执行 `npm run pack`，重新生成 `dist` 和 ZIP。
- 构建后核对 `dist/manifest.json`、`dist/index.html` 相对资源路径和 ZIP 根目录内容。
- 不将“构建成功”等同于所有浏览器 API 已实测；未实际验证的扩展能力不得宣称已完成真实环境测试。
- 最终回复简要说明完成内容、必要使用条件和验证结果，并提供更新后的交付物链接。
